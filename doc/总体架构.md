
# 总体架构

> 状态：与当前实现同步 ｜ 定位：各模块设计文档的上位文档，模块细节见对应文档

## 1. 定位与范围

本文档定义扩展的整体模块划分、职责边界与交互规则。模块级契约、流程与实现细节由各模块设计文档描述，本文只回答三个问题：有哪些模块、谁依赖谁、数据如何流动。

## 4. 依赖规则

以下规则对所有模块**必须**成立：

1. 依赖方向严格单向：**UI → 服务 → HAL → 硬件**；
2. 第三方串口包的唯一触碰点是 `SerialPortHalImpl`，其余任何模块**不得** import serialport；
3. 服务层之间**不得**依赖对方实现，只允许通过 Detector 导出的设备模型接口与事件通道交互；
4. 模块装配只发生在 `extension.ts`；默认 Consumer 通过工厂注入，服务层不依赖 Consumer 实现；
5. 设备状态（连接状态）的唯一写者是 ConnectionService；视图与 Connection 只读；
6. 连接参数由调用方随 `connect(device, config)` 传入，ConnectionService 不依赖配置存储（自动恢复场景时再评估注入）。

## 5. 核心数据流

### 5.1 设备事件流（Detector 驱动）

```mermaid
sequenceDiagram
    participant D as Detector
    participant H as HAL
    participant V as TreeView
    participant C as ConnectionService

    loop 轮询周期（视图可见时）
        D->>H: listDevices()
        H-->>D: SerialPortInfo[]
    end
    D->>D: 快照对比（增删 / 身份变化）
    D->>V: onDidChangeDevices({ added, removed })
    D->>C: onDidChangeDevices({ added, removed })
    par 视图更新
        V->>V: 按 added/removed 增删 item → fire()
    and 资源清理
        C->>C: 按 removed 销毁对应 Connection
    end
```

设备拔除的资源清理由事件自动驱动；任何模块**不得**在扫描逻辑之外"顺便"清理连接资源。

### 5.2 连接与断开（用户驱动）

```mermaid
sequenceDiagram
    actor U as 用户
    participant V as TreeView
    participant C as ConnectionService
    participant H as HAL
    participant Conn as Connection
    participant T as Terminal

    U->>V: 点击连接
    V->>C: connect(device)
    C->>C: 守卫：status 非 disconnected 拒绝
    Note over C: 按 identity 载入配置（规划中，当前默认 115200）
    C->>H: openPort(options)
    alt 打开成功
        H-->>C: SerialPortHandle
        C->>Conn: new Connection(device, handle)
        Conn->>T: addConsumer（默认 Consumer）
        C->>V: onDidChangeDeviceStatus(connected) → 重渲染
    else 打开失败
        H-->>C: Error（原因明确）
        C->>V: 状态回滚 disconnected + 提示原因
    end
```

```mermaid
sequenceDiagram
    actor U as 用户
    participant V as TreeView
    participant C as ConnectionService
    participant Conn as Connection
    participant T as Terminal
    participant D as Detector

    alt 视图断开
        U->>V: 点击断开
        V->>C: disconnect(device)
    else 终端面板关闭
        U->>T: 关闭面板
        T->>Conn: requestDisconnect()
        Conn->>C: onCloseRequested
    else 设备拔除（事件驱动）
        D->>C: onDidChangeDevices({ removed })
    end
    C->>Conn: close() → 各 Consumer.onClosed()
    Conn-->>C: 端口已关闭
    C->>V: onDidChangeDeviceStatus(disconnected) → 重渲染
```

三个断开入口均收敛于 Service 的单一销毁入口，见 SerialPortConnection设计.md「断开回传机制」。

### 5.3 数据流（Connection 驱动）

```mermaid
sequenceDiagram
    participant P as 串口设备
    participant H as HAL
    participant Conn as Connection
    participant T as Terminal
    participant W as 其他 Consumer

    P->>H: 数据字节流
    H->>Conn: handle.onData(data)
    Conn->>T: consumer.onData(data)
    Conn->>W: consumer.onData(data)
    T->>T: 原字符串写入终端面板
```

Connection 只广播不加工；Consumer 之间的协作不经过 Connection。

## 6. 组件生态

- 连接建立后，ConnectionService 通过工厂注册默认 Consumer（SerialPortTerminal）；
- 未来支持多 Consumer（SerialPortDataPaster 等）注册与二级菜单管理（M4）；
- Consumer 关闭行为由类型自决：用户可见类型保留视图并提示断开，不可见类型直接销毁（见 SerialPortConsumer设计.md「关闭行为约定」）；
- 减为零规则：某设备的 Consumer 全部移除时，关闭串口并销毁 Connection。

## 8. 路线图

- **M3** 终端完善：输入增强（历史、行尾符配置）、Parser 与字符转义；
- **M4** 快捷配置（当前里程碑）：配置管理 UI（命名集合、子节点展示、增/改名/删）已实现，剩余配置连接与自定义参数向导（见 SerialPortQuickConfig设计.md 分阶段计划）；
- **M5** 数据转发：多 Consumer 注册、二级菜单管理、减为零自动关串口；
- **M6** 自动化：设备参数配置与持久化收尾、日志保存、启动自动恢复。
