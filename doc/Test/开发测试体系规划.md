# 开发测试体系规划

> 状态：规划中（P0 已定稿，待实现）｜ 目录：`test/` ｜ 上位文档：[总体架构.md](../总体架构.md) ｜ 关联：[SerialPortHalVirtual规划.md](../Hal/SerialPortHalVirtual规划.md)

## 1. 定位

工程设施而非运行期功能：为本项目的模块与类维护自动化测试用例，在开发环境中回归验证。不改变扩展的运行期行为，不单独占用版本，随下一次功能发布顺带带入。

## 2. 现状与动机

- **现状**：无测试脚本、无测试框架依赖、无测试目录，`scripts` 仅有 compile / watch / clean / prepublish；
- **动机**：
  - 项目存在大量回归敏感的纯逻辑——身份退化链、配置多形态解析、ANSI 剥离、行缓冲、日志分割；
  - v1.2.2 / v1.2.3 的快捷配置存储事故表明持久化兼容需要回归护栏；
  - 「移除 legacy 兼容」待办（见 [SerialPortQuickConfig设计.md](../SerialPortQuickConfig设计.md) §9）属破坏性改动，执行前应有测试保障。

## 3. 测试分层

### P0 单元测试（先行）

- 运行环境：Node 内置 `node:test`，零新增依赖（Node ≥ 20 即可，当前 v24）；
- 范围：纯逻辑模块——`vscode` API 经模块桩（见 §5.2）提供最小实现后，`import vscode` 的纯逻辑模块同样纳入 P0；
- 构建集成：`tsc` 双配置编译（主配置产物 `dist/`、测试配置产物 `out-test/`），`node --test out-test/unit/` 运行，不引入 tsx 等第三方运行器。

### P1 集成测试

- 运行环境：`@vscode/test-electron` 启动扩展开发宿主，`vscode` API 真实可用；
- 数据层：全部运行在 [SerialPortHalVirtual](../Hal/SerialPortHalVirtual规划.md) 之上——集成测试与产品测试模式共用装配缝与虚拟设备，真实串口仅保留手动冒烟；
- 场景：连接/断开生命周期、状态事件回写、Consumer 注册与减为零关闭、日志落盘与分割、AgentBridge TCP 收发、快捷配置 CRUD 与引用计数。

### P2 CI

GitHub Actions 工作流，Windows 环境跑 P0 + P1（Linux 需 xvfb，后评估）。

## 5. 工程方案（P0 定稿）

### 5.1 目录与构建

- 测试源码：`test/unit/<模块名>.test.ts`；模块桩：`test/mocks/install-vscode-stub.cjs`（手写 CJS，免编译，安装器与替身同文件）；
- 新增 `tsconfig.test.json`（extends 主配置）：`rootDir: .`、输出 `out-test/`、`types: ["node"]`、include `test + src`；
- npm 脚本：`compile:test` = `tsc -p tsconfig.test.json`（测试与源码一并编译到 `out-test/`）；`test` = `compile:test` + `node --require ./test/mocks/install-vscode-stub.cjs --test "out-test/test/unit/**/*.test.js"`（用 glob 精确匹配测试文件，目录路径会被运行器当作单文件加载）；
- 发布门禁：`vscode:prepublish` 以 `npm test` 为前置，套件红时 `vsce package` / `vsce publish` 直接中止——机械保证失败状态不发布；后续 HalVirtual P0 的编译期开关校验将在同一脚本串联；
- `.vscodeignore` 追加 `test/**`、`out-test/**` 与 `tsconfig.test.json`，发布包不含测试代码、产物与配置。

### 5.2 vscode 模块桩

P0 目标模块中仅 AnsiStripper 无 `vscode` 导入；其余三个经 `--require` 预加载的安装器劫持 `Module._load`，把 `'vscode'` 重定向到测试替身，业务源码零改动。替身最小成员：

| 成员 | 实现 |
|---|---|
| `EventEmitter<T>` | 基于 `node:events` 适配 `event` / `fire` / `dispose` |
| `l10n.t(msg, ...args)` | `{n}` 占位符替换 |
| `workspace.getConfiguration(section)` | 可编程配置表，`get(key, defaultValue)` 返回测试注入值 |
| `Memento` | 仅构造参数类型，测试经 `FakeMemento`（Map 实现 `get` / `update`）鸭子类型注入 |

若后续遇到桩覆盖不了的场景，再评估业务源码去 `vscode` 化重构（本 P0 不动任何业务源码）。

### 5.3 时钟与稳定性

`SerialPortLineTimestampBuffer` 内部直接取 `new Date()`，不做时钟注入：断言采用两类无 flake 策略——无占位符自定义格式（输出恒定）与 `{SSS}` 格式（只断言 `\[\d{3}\]` 结构），不使用依赖墙钟精确值的断言。

### 5.4 测试套件版本

- 套件版本独立于产品版本，位于 `test/package.json`（`private: true`），与产品 `package.json` 互不影响；
- 语义：新增测试文件或框架 / 运行方式变更 → minor +1；用例修正、桩调整 → patch +1；P0 全部落地且 `npm test` 全绿 → `1.0.0`；
- 产品版本与 CHANGELOG 不随测试变更更新；commit message 采用 `version` + `unit test version` 双 trailer，格式见 commit-message-format skill；
- 每次套件版本变更在 §9 变更记录表登记。

## 7. 风险与规避

| 风险 | 规避 |
|---|---|
| serialport 原生模块在测试宿主内 ABI 不匹配 | 集成测试在测试宿主内启用产品测试模式注入虚拟 HAL，真实 `SerialPortHalImpl` 不参与自动化测试 |
| `vscode` API 无法在纯 Node 进程加载 | P0 经模块桩提供最小实现（见 §5.2）；依赖真实 `vscode` 运行时的场景归入 P1 |
| 集成测试需下载独立 VS Code 实例 | 首次运行耗时与离线环境受限属已知代价；显示依赖仅在 Linux CI 出现，P2 再处理 |
| 跨 chunk ANSI 序列残留 | 契约已定为行缓冲式剥离（§6.1），残余风险收敛为实现进度：改造前跨 chunk 序列仍存在前缀贪婪剥离与残段泄漏，改造牵动 LogRecorder / AgentBridge 调用与断开收尾 |
