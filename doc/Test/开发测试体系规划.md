# 开发测试体系规划

> 状态：规划中 ｜ 目录：`test/`（待建）｜ 上位文档：[总体架构.md](../总体架构.md) ｜ 关联：[SerialPortHalVirtual规划.md](../Hal/SerialPortHalVirtual规划.md)

## 1. 定位

工程设施而非运行期功能：为本项目的模块与类维护自动化测试用例，在开发环境中回归验证。不改变扩展的运行期行为，不单独占用版本，随下一次功能发布顺带带入。

## 2. 现状与动机

- **现状**：无测试脚本、无测试框架依赖、无测试目录，`scripts` 仅有 compile / watch / clean / prepublish；
- **动机**：
  - 项目存在大量回归敏感的纯逻辑——身份退化链、配置多形态解析、ANSI 剥离、行缓冲、日志分割；
  - v1.2.2 / v1.2.3 的快捷配置存储事故表明持久化兼容需要回归护栏；
  - 「移除 legacy 兼容」待办（见 [SerialPortQuickConfig设计.md](../SerialPortQuickConfig设计.md) §9）属破坏性改动，执行前应有测试保障。

## 3. 测试分层

### P0 单元测试（先行）

- 运行环境：Node 内置 `node:test`，零新增依赖；
- 范围：不依赖 `vscode` API 的纯逻辑模块——`vscode` 模块只能在扩展宿主内加载，纯 Node 进程不可用；
- 构建集成：`npm test` = clean + compile + 对编译产物运行 `node --test`；是否改用 tsx 直跑 TS 源码，实现时定。

### P1 集成测试

- 运行环境：`@vscode/test-electron` 启动扩展开发宿主，`vscode` API 真实可用；
- 数据层：全部运行在 [SerialPortHalVirtual](../Hal/SerialPortHalVirtual规划.md) 之上——集成测试与产品测试模式共用装配缝与虚拟设备，真实串口仅保留手动冒烟；
- 场景：连接/断开生命周期、状态事件回写、Consumer 注册与减为零关闭、日志落盘与分割、AgentBridge TCP 收发、快捷配置 CRUD 与引用计数。

### P2 CI

GitHub Actions 工作流，Windows 环境跑 P0 + P1（Linux 需 xvfb，后评估）。

## 4. 目标模块清单

| 模块 | 层级 | 重点用例 |
|---|---|---|
| SerialPortAnsiStripper | P0 | 各类转义序列剥离、控制字符保留、转义序列跨 chunk 到达 |
| SerialPortLineTimestampBuffer | P0 | chunk 边界半行缓冲、flush 补全、关闭时间戳时透传 |
| SerialPortDeviceDetector 身份与对比 | P0 | 退化链三级判定、同路径身份变化、added/removed 明细 |
| SerialPortConfigStore | P0 | 校验规则、引用计数归零删除、legacy 两种形态读取 |
| 虚拟设备画像 | P0 | 命令应答表、行缓冲、远端回显（随 SerialPortHalVirtual 落地补充） |
| SerialPortConnectionService | P1 | 连接守卫、断开单一入口、状态事件序列 |
| SerialPortLogRecorder | P1 | 延迟建文件、暂停/继续、按大小分割 |
| SerialPortAgentBridge | P1 | 多客户端广播、ANSI 剥离透传、断开清理 |

## 5. 约定与决策点

- 测试文件位置：`src` 内 `*.test.ts` 随源码 vs 独立 `test/` 目录——实现前定稿，倾向独立目录（避免测试代码混入 dist 发布产物）；
- 断言与测试结构：仅用 `node:test` 内置能力，不引入 chai / sinon；
- 覆盖率统计不作为首版目标。

## 6. 风险与规避

| 风险 | 规避 |
|---|---|
| serialport 原生模块在测试宿主内 ABI 不匹配 | 集成测试在测试宿主内启用产品测试模式注入虚拟 HAL，真实 `SerialPortHalImpl` 不参与自动化测试 |
| `vscode` API 无法在纯 Node 进程加载 | 单元测试范围限定为无 vscode 依赖的模块；依赖 `vscode.EventEmitter` 的模块归入 P1 |
| 集成测试需下载独立 VS Code 实例 | 首次运行耗时与离线环境受限属已知代价；显示依赖仅在 Linux CI 出现，P2 再处理 |

## 7. 演进路线

- [ ] P0：`test/` 目录、`npm test` 脚本、AnsiStripper 与 LineTimestampBuffer 用例；
- [ ] P0：Detector 身份与对比、ConfigStore 校验与兼容用例；
- [ ] P1：`@vscode/test-electron` 骨架与虚拟 HAL 装配（依赖产品测试模式 P0 落地）；
- [ ] P1：连接生命周期、日志、AgentBridge 场景用例；
- [ ] P2：GitHub Actions 工作流。
