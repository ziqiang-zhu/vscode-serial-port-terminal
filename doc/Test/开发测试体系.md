# 开发测试体系

> 状态：与当前实现同步 ｜ 定位：测试体系的正式描述文档——`test/` 目录、npm 测试链路、分层策略、工程方案、全部用例清单与套件变更记录 ｜ 上位文档：[总体架构.md](../总体架构.md) ｜ 关联：[SerialPortHalVirtual规划.md](../Hal/SerialPortHalVirtual规划.md)、[编译指导.md](../编译指导.md)

## 1. 定位

工程设施而非运行期功能：为本项目的模块与类维护自动化测试用例，在开发环境中回归验证。不改变扩展的运行期行为，不单独占用产品版本，随下一次功能发布顺带带入。

测试体系重点守护三类回归敏感面：

- **纯逻辑管线**：设备身份退化链、配置多形态解析与引用计数、ANSI 剥离、行缓冲、日志分割；
- **持久化兼容**：快捷配置为 globalState 里的用户数据，存储结构改动必须有回归护栏；
- **破坏性改动的先行保障**：兼容移除等破坏性改动执行前，先以测试固化既有行为。

## 2. 设计目标

- **零硬件回归**：数据层全部运行在虚拟 HAL 之上（真实串口仅保留手动冒烟——真实 COM 口数量不定，自动化断言只针对虚拟侧）；
- **业务源码零改动可测**：`vscode` API 经模块桩替换（P0），集成测试在扩展开发宿主内自装配（P1）；
- **失败状态不发布**：`vscode:prepublish` 以 `npm test` 为前置，套件红时 `vsce package` / `vsce publish` 直接中止——机械保证失败状态不发布；
- **测试不进发布包**：`.vscodeignore` 屏蔽 `test/**`、`out-test/**` 与测试编译配置。

## 3. 测试分层

### P0 单元测试

- 运行环境：Node 内置 `node:test`，零新增依赖（Node ≥ 20 即可，当前 v24）；
- 范围：纯逻辑模块——`vscode` API 经模块桩（见 §5.2）提供最小实现后，`import vscode` 的纯逻辑模块同样纳入 P0；
- 构建集成：`tsc` 双配置编译（主配置产物 `dist/`、测试配置产物 `out-test/`），`node --test out-test/unit/` 运行，不引入 tsx 等第三方运行器。

### P1 集成测试

- 运行环境：`@vscode/test-electron` 启动扩展开发宿主（**新开独立窗口**：隔离 user-data、干净扩展环境，不影响开发中窗口），`vscode` API 真实可用；测试框架 mocha（bdd 接口），经 `extensionTestsPath` 的 `run()` 契约启动；宿主二进制按探测链选取——本机已安装 VS Code（`code --version` ≥ engines 要求 1.95）→ 已缓存的下载实例 → 下载兜底；本机开发零下载，CI（P2）走下载；
- 运行器：`npm run test:integration`（`scripts/run-integration-tests.js`）——以**测试构建**编译 `dist/`（`USE_VIRTUAL_HAL=true`）→ 编译测试 → `runTests` → 结束后**恢复产品构建** `dist/`；运行中断的残留由下次构建覆盖，prepublish 链恒重新产品构建，发布不受影响；
- 装配两路：黑盒 1 例验证真实装配路径（扩展激活 + 核心命令注册）；场景用例在扩展宿主内**自装配**（require 业务模块 + 鸭子类型 context `{ subscriptions: [] }` + 虚拟 HAL 混排）——服务协作与真实 `vscode` API（EventEmitter / workspace / window / fs / net）全部真实，不侵入产品代码、不依赖 UI 树选择；
- 数据层：全部运行在 [SerialPortHalVirtual](../Hal/SerialPortHalVirtual规划.md) 之上——集成测试与产品测试模式共用装配缝与虚拟设备，真实串口仅保留手动冒烟；
- 场景：连接/断开生命周期、状态事件回写、Consumer 注册与减为零关闭、日志落盘与分割、AgentBridge TCP 收发、开机链路端到端、控制台视图可解析；快捷配置 CRUD 与引用计数已由 P0 单测覆盖（20 例），集成不重复。

### P2 CI（搁置）

GitHub Actions 工作流，Windows 环境跑 P0 + P1（Linux 需 xvfb，后评估）。重启条件与记录见 [当前计划与待办.md](../当前计划与待办.md) §四。

## 5. 工程方案

### 5.1 目录与构建

- 测试源码：`test/unit/<模块名>.test.ts`；模块桩：`test/mocks/install-vscode-stub.cjs`（手写 CJS，免编译，安装器与替身同文件）；
- 新增 `tsconfig.test.json`（extends 主配置）：`rootDir: .`、输出 `out-test/`、`types: ["node"]`、include `test + src`；
- npm 脚本：`compile:test` = `tsc -p tsconfig.test.json`（测试与源码一并编译到 `out-test/`）；`test` = `compile:test` + `node --require ./test/mocks/install-vscode-stub.cjs --test "out-test/test/unit/**/*.test.js"`（用 glob 精确匹配测试文件，目录路径会被运行器当作单文件加载）；`test:integration` = `scripts/run-integration-tests.js`（见 §3 P1：测试构建 → `runTests` → 恢复产品构建）；
- P1 集成目录：`test/integration/index.ts`（导出 `run()` 契约：组装 mocha 并加载 `suite/*.test.js`）与 `test/integration/suite/`（用例文件）；mocha 以 devDependency 引入（VS Code 新版不再内置可 require 的 mocha），`tsconfig.test.json` 的 `types` 追加 `mocha`；集成用例不匹配单测 glob（`test/unit/**`），`npm test` 不加载它们；
- 发布门禁：`vscode:prepublish` 以 `npm test` 为前置，套件红时 `vsce package` / `vsce publish` 直接中止——机械保证失败状态不发布；
- `.vscodeignore` 追加 `test/**`、`out-test/**` 与 `tsconfig.test.json`，发布包不含测试代码、产物与配置。

### 5.2 vscode 模块桩

P0 目标模块中仅 AnsiStripper 无 `vscode` 导入；其余四个（LineTimestampBuffer / ConfigStore / DeviceImpl / Detector）经 `--require` 预加载的安装器劫持 `Module._load`，把 `'vscode'` 重定向到测试替身，业务源码零改动。替身最小成员：

| 成员 | 实现 |
|---|---|
| `EventEmitter<T>` | 基于 `node:events` 适配 `event` / `fire` / `dispose` |
| `l10n.t(msg, ...args)` | `{n}` 占位符替换 |
| `workspace.getConfiguration(section)` | 可编程配置表，`get(key, defaultValue)` 返回测试注入值 |
| `workspace.onDidChangeConfiguration` | 返回一次性 Disposable（单测不触发配置变更） |
| `window.showErrorMessage` | 记录到桩内数组，经 `__shownErrorMessages()` 断言（测试专用钩子，同 `__setConfiguration` 定位） |
| `window.showInformationMessage` | 同上，经 `__shownInfoMessages()` 断言 |
| `Memento` | 仅构造参数类型，测试经 `FakeMemento`（Map 实现 `get` / `update`）鸭子类型注入 |

若遇到桩覆盖不了的场景，再评估业务源码去 `vscode` 化重构。

### 5.3 时钟与稳定性

`SerialPortLineTimestampBuffer` 内部直接取 `new Date()`，不做时钟注入：断言采用两类无 flake 策略——无占位符自定义格式（输出恒定）与 `{SSS}` 格式（只断言 `\[\d{3}\]` 结构），不使用依赖墙钟精确值的断言。

### 5.4 测试套件版本

- 套件版本独立于产品版本，位于 `test/package.json`（`private: true`），与产品 `package.json` 互不影响；
- 语义：新增测试文件或框架 / 运行方式变更 → minor +1；用例修正、桩调整 → patch +1；
- 产品版本不随测试变更更新；commit message 采用 `version` + `unit test version` 双 trailer，格式见 commit-message-format skill；
- **套件变更只在本文件 §8「变更记录」登记，不写入产品 CHANGELOG.md**（2026-11-21 起；此前随产品发布带入 CHANGELOG 的「单元测试」条目为历史记录，维持原状不再新增）。

## 6. 用例清单

### 6.1 SerialPortAnsiStripper（19 例，行缓冲契约）

> **契约**：以 `\n` 为行单位，转义序列不跨行生效；未获得换行时尾行跨调用保留，`flush()` 刷出剩余半行。API 为 `process(data: Buffer): Buffer` + `flush(): Buffer`。

| # | 用例 | 目标契约预期 |
|---|---|---|
| 1 | 完整行含 CSI 颜色码 | `RED\n` |
| 2 | 单 chunk 多行混合序列 | 逐行剥离 |
| 3 | 行首/行中/行尾序列 | 均剥离 |
| 4 | OSC（BEL 终止）行 | 整段剥离 |
| 5 | C1（0x9B）行 | 剥离 |
| 6 | 清屏/光标归位行 | 剥离 |
| 7 | 无序列普通行 | 原样 |
| 8 | 无换行 chunk | 返回空，半行保留 |
| 9 | 序列跨 chunk 边界（同一条行内） | 续全后完整剥离：`foobar\n` |
| 10 | 一行跨三个 chunk 累积 | 一次完整输出 |
| 11 | 多字节字符跨 chunk 按字节拆分 | 字节级缓冲，不产生替换符 |
| 12 | CRLF 行 | `\r` 属行内容，原样保留 |
| 13 | 行尾悬挂 ESC | 按字面保留（序列不跨行等待） |
| 14 | 行尾截断序列（末字节为终止符候选） | 行内剥离，无残留 |
| 15 | 连续空行 + 裸 reset 行 | 逐行输出 |
| 16 | 完整行含中文 | 中文完好 |
| 17 | 逐字节喂入与单 chunk 等价 | 输出一致（含多字节拆分） |
| 18 | 无换行 chunk 保留 | `flush()` 刷出剩余半行 |
| 19 | `process` / `flush` API | 存在 |

### 6.2 SerialPortLineTimestampBuffer（20 例，行缓冲契约）

> **契约**：按 `\n` 行缓冲加时间戳，未完成尾行跨调用保留、`flush()` 刷出；格式经 workspace 配置注入，空 / 空白回退默认；同一 chunk 内各行共享同一时间戳（每 chunk 计算一次）。

| # | 用例 | 目标契约预期 |
|---|---|---|
| 1 | 无占位符自定义格式 `T\|` | 每行恒定前缀 `T\|` |
| 2 | 默认格式（未注入配置） | 前缀匹配 `\[\d{2}:\d{2}:\d{2}\.\d{3}\]` |
| 3 | 空白格式配置 | 回退默认格式 |
| 4 | 空字符串格式配置 | 回退默认格式 |
| 5 | `{SSS}` 格式 | 前缀匹配 `\[\d{3}\]` |
| 6 | 全占位符组合 | 全部替换、无残留 |
| 7 | 未知 token（如 `{X}`） | 按字面保留 |
| 8 | 单 chunk 多行 | 逐行加前缀 |
| 9 | 半行保留至换行 | 补全后输出 |
| 10 | 一行跨三个 chunk 累积 | 一次完整输出 |
| 11 | flush 空 | 返回空 |
| 12 | flush 半行 | 补前缀刷出 |
| 13 | flush 后状态复位 | 后续处理不受影响 |
| 14 | 空行 | 同样加前缀 |
| 15 | CRLF 行 + 完整行中文 | `\r` 保留、中文完好 |
| 16 | 连续 process 轮次 | 无残留污染 |
| 17 | 空 chunk | 返回空 |
| 18 | 多字节字符跨 chunk 按字节拆分 | 字节级缓冲，不产生替换符 |
| 19 | 同 chunk 各行共享时间戳 | 前缀一致（每 chunk 计算一次） |
| 20 | 完整行后接剥离器 flush 的半行 | 半行保留、flush 补前缀刷出 |

### 6.5 虚拟设备画像（HalVirtual P0：骨架 + Echo，11 例）

### 6.6 虚拟命令壳画像（HalVirtual P1：Linux / U-Boot，20 例）

> **契约**：见 [SerialPortHalVirtual规划.md](../Hal/SerialPortHalVirtual规划.md) §4.2/§4.3/§4.5、§10.2。远端回显（`\r` 回显 `\r\n`）、按 `\r`/`\n` 行缓冲、内置表 + 应答目录覆盖（精确文件 > 精确内置 > 参数化内置 > 未知回退）、复合命令按 `;` 依次执行；应答与提示符行尾 `\r\n`。`interactionDir` 经构造注入（临时目录 + fs 读写验证覆盖逻辑）。

| # | 用例 | 断言要点 |
|---|---|---|
| 1 | 注册三台设备 | `listDevices` 返回 ECHO / LINUX / UBOOT 三项，均 manufacturer=`Virtual` |

| 3 | 远端回显字符 | 键入字符逐字回显，`\r` 回显为 `\r\n` |

### 6.12 SerialPortLogRecorder 写盘失败语义（P0，3 例）

> **契约**：写盘失败（磁盘满 / 目录不可写等）每次都提示「写入日志失败」（不去重）；错误流丢弃后下一块数据重建流重新尝试——总是允许尝试保存，恢复后自动续记；文件以流 `open` 事件确认创建成功（`fileCreated` 由 open 置位），「文件已保存」提示以确认为前提（打开失败则停止时不弹）。真实 fs + 临时目录：以"父目录位置被文件占用"制造确定性 open 失败；提示经桩记录器断言（快照增量），刷盘与错误事件异步到达、轮询等待。

| # | 用例 | 断言要点 |
|---|---|---|
| 1 | 正常落盘基线 | 文件创建 → 「已保存」提示一次、内容正确落盘、零错误提示（open 确认正路径） |

| 3 | 失败后重试与每次提示 | 后续数据重建流重试（仍失败）、每次失败都提示（共两次）、「已保存」不出现 |
