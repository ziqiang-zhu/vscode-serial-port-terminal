# 编译指导

> 状态：P4 已实现（随 HalVirtual P4 落地）｜ 关联：[总体架构.md](总体架构.md) ｜ [SerialPortHalVirtual规划.md](Hal/SerialPortHalVirtual规划.md) §5 ｜ [开发测试体系规划.md](Test/开发测试体系规划.md) §5

## 1. 定位

本项目存在三种编译形态：面向发布的产品构建、面向无硬件开发调试的测试构建，以及面向回归验证的单元测试编译。三者共用同一份源码，形态差异全部在**编译/打包期**决定，运行期不存在任何切换开关。本文档指导开发者按需选择模式、说明各模式的配置方法与实现原理。

## 2. 编译模式总览

| 模式 | 入口 | F5 入口 | 产物目录 | HAL 形态 | 虚拟设备控制台 | 用途 |
|---|---|---|---|---|---|---|
| **产品构建**（Product） | `npm run compile` | `Debug (real HAL)` | `dist/` | 仅真实设备（`SerialPortHalImpl`） | 注册提供器并渲染占位页（发布 VSIX 经清单净化不可见） | 发布 VSIX 的形态；真实串口调试 |
| **测试构建**（Test，虚拟混排） | `USE_VIRTUAL_HAL=true npm run compile` | `Debug`（默认） | `dist/` | 真实 + 虚拟混排（`SerialPortHalComposite`，`VCOM-` 前缀归虚拟） | 可用（侧边栏 Virtual Device Console） | 无硬件开发调试：虚拟设备、开机链路、控制面 |
| **单元测试编译**（Unit Test） | `npm test` | — | `out-test/` | 不产出可运行扩展（vscode 模块桩环境） | 不可用 | 149 例单测回归（`doc/Test/开发测试体系规划.md`） |

三种模式的选择规则：

- 日常开发调试：直接 F5（默认 `Debug` 配置即测试构建），设备树同时出现真实 COM 口与 `VCOM-` 虚拟设备，侧边栏可用虚拟设备控制台；
- 需要调真实串口链路：切换到 `Debug (real HAL)` 配置，仅真实设备（虚拟 HAL 代码不参与装配）；
- 提交前回归：`npm test`，要求全绿；
- 打包发布：**必须** `npm run package`（禁止直接 `vsce package`，见 §4.3），产出产品化 VSIX。

## 3. 各模式配置方法

### 3.1 产品构建（Product）

```
npm run compile          # tsc 编译到 dist/（原子构建，见 §4.5）
```

或 F5 选择 `Debug (real HAL)` 配置（preLaunchTask 为默认 `compile` 任务）。不带任何构建参数即产品形态——**默认即产品**是所有构建路径的安全底线（prepublish、CI、clone 后直接构建均落到此形态）。

### 3.2 测试构建（Test，虚拟混排）

```
# 命令行（跨平台环境变量语法以实际 shell 为准）
USE_VIRTUAL_HAL=true npm run compile
```

或直接 F5（默认 `Debug` 配置，preLaunchTask 为 `compile:test-hal` 任务，任务经 `options.env` 注入 `USE_VIRTUAL_HAL=true`）。

测试构建相对产品构建的行为差异：

- 设备树 = 真实设备 + 4 台虚拟设备（`VCOM-ECHO` / `VCOM-LINUX` / `VCOM-UBOOT` / `VCOM-REPLAY`）并集，真实在前；
- `VCOM-UBOOT` 打开后走开机链路（自动开机倒计时 → `boot` 或到期切 Linux 会话，见 [SerialPortHalVirtual规划.md](Hal/SerialPortHalVirtual规划.md) §4.3）；
- 侧边栏出现 Virtual Device Console 面板（在线/拔出、背压、延迟、回放控制、设备侧注入）；
- 5 个 `serialPortTerminal.testMode.*` 设置生效（回放文件/速率/循环、应答延迟、应答目录）；
- 调试控制台首行构建指纹标注形态（§4.4），用于核对宿主加载的版本与构建模式。

### 3.3 单元测试编译（Unit Test）

```
npm test                 # tsc -p tsconfig.test.json + node:test 运行 out-test/test/unit/
```

独立编译配置 `tsconfig.test.json`（测试与源码一并编译到 `out-test/`，`types: ["node", "mocha"]`——mocha 类型供集成测试使用）；`vscode` 模块经 `test/mocks/install-vscode-stub.cjs` 桩替换，业务源码零改动。测试直接构造虚拟 HAL 实例（不经 `halSelection` 装配），三种模式中只有它不需要 `dist/`。详见 [开发测试体系规划.md](Test/开发测试体系规划.md) §5。

### 3.4 集成测试

```
npm run test:integration    # @vscode/test-electron 启动独立 VS Code 宿主执行 21 例场景用例
```

运行器以测试构建编译 `dist/`（虚拟混排）→ 启动宿主 → 结束后自动恢复产品构建；宿主二进制优先探测本机已安装 VS Code（零下载），无则退回下载。详见 [开发测试体系规划.md](Test/开发测试体系规划.md) §3 P1。

### 3.5 打包发布（产品化 VSIX）

```
npm run package          # 净化清单 → vsce package → 恢复清单（见 §4.3）
```

发布 VSIX 必须是产品化状态：不含 Virtual Device Console 面板、不含 `testMode.*` 设置项与对应本地化键。**禁止直接 `vsce package` / `vsce publish`（不带 VSIX 路径）**——prepublish 链中的清单校验会机械拦截（§4.3）。发布流程：`npm run package` 生成 `.vsix` 后，`vsce publish <vsix 路径>` 上传。

## 4. 实现原理

### 4.1 编译期开关与产物注入

开关常量 `USE_VIRTUAL_HAL` 位于 `src/hal/halSelection.ts`，**源码字面量恒为 `false`**（发布就绪状态，永不手动修改）。测试构建的开关值由构建脚本在**产物级**注入：

1. `scripts/build.js` 先以 tsc 将源码原样编译到 `.tmp-build/`；
2. 读取环境变量 `USE_VIRTUAL_HAL`，为 `true` 时把产物 `hal/halSelection.js` 中的 `exports.USE_VIRTUAL_HAL = false` 字面量替换为 `true`；
3. 替换后断言恰好命中 1 处——tsc 发射格式变化时构建**响亮失败**而非静默失效；
4. 替换发生在写指纹之前、原子交换（`.tmp-build` → `dist`）之前，`dist/` 任何时刻只存在完整一致的形态。

设计约束：开关仍是编译期决定（产物在构建时定型），运行期不存在切换，不违背 [SerialPortHalVirtual规划.md](Hal/SerialPortHalVirtual规划.md) §5「编译期隔离」。

### 4.2 构建任务与调试配置

`.vscode/tasks.json` 定义两个构建任务：默认 `compile`（产品构建）与 `compile:test-hal`（`options.env` 注入 `USE_VIRTUAL_HAL=true`）。`.vscode/launch.json` 的两个配置分别挂接：`Debug` → `compile:test-hal`（日常 F5 即测试构建），`Debug (real HAL)` → `compile`。

### 4.3 产品化打包（清单净化 + 机械拦截）

VS Code 的 `contributes.views` / `configuration` 是打包时随 `package.json` 进入 VSIX 的静态清单，无法运行期隐藏；产品化由打包包装脚本完成：

1. `scripts/package.js`（`npm run package`）先将 `package.json` / `package.nls.json` 字节级备份到临时文件；
2. 对清单做**净化**：移除 `serialPortConsole` 视图条目、5 个 `testMode.*` 配置项及对应 6 个本地化键；移除前有结构断言（条目必须存在，结构漂移时失败退出）——移除后校验由 `vsce` 触发的 prepublish 链中的 `verify-release-manifest.js` 承担；
3. 净化后启动 `vsce package` 子进程——此时磁盘上的清单已是产品化版本，VSIX 必然不含测试特性；
4. 打包结束（无论成败）`finally` 恢复原清单文件，git 工作区不留痕迹。

**机械拦截**：`vscode:prepublish` 链为 `npm test` → `verify-hal-selection.js`（源码开关恒 `false`）→ `verify-release-manifest.js`（清单已净化）→ `npm run compile`。绕过包装脚本直接 `vsce package` 时清单未净化，`verify-release-manifest.js` 检出测试条目即非零退出、拒绝打包。

净化边界：`dist/` 产物中虚拟 HAL / 控制台视图的编译物仍存在，但在产品构建中运行时**不可达**（装配走纯真实 HAL 分支；提供器注册对应不到清单声明的视图，永不 resolve）。彻底剔除需引入打包器做 tree-shaking，当前不为此引入构建依赖。

### 4.4 构建指纹

`dist/build-info.json`（由 `scripts/build.js` 写入）记录 `builtAt` / `commit` / `virtualHal` 三项；扩展激活时在调试控制台输出首行（如 `[Serial Port Terminal] build <时间戳> @ <commit> (test build (virtual HAL))`，产品构建为 `(product build)`——形态后缀由 `virtualHal` 字段映射），用于核对宿主加载的产物版本与形态（时间戳非刚才 = 旧产物）。

### 4.5 原子构建

`scripts/build.js` 采用「编译到 `.tmp-build/` → 成功后整体 rename 替换 `dist/`」的原子流程：tsc 失败或中途被杀时 `dist/` 保持上一个完整版本，杜绝半成品被调试宿主加载。

### 4.6 测试隔离

测试用例不进入发布包：`.vscodeignore` 排除 `test/**`、`out-test/**`、`tsconfig.test.json`（见 [开发测试体系规划.md](Test/开发测试体系规划.md) §5.1）；发布 VSIX 的 `dist/` 仅含业务编译物。

### 4.7 README 链接书写规则

`README.md` / `README.en.md` 同时服务于三个渲染环境：GitHub 仓库页、Marketplace 扩展详情页、本地扩展详情面板。`vsce` 打包时会把 README 中的 **Markdown 相对链接**自动重写为基于 `package.json` `repository` 字段的 GitHub 绝对 URL（依据 v1.4.4 实测：HTML 链接不受此重写保护），因此：

- **优先使用纯 Markdown 编写 README，尽量少用 HTML 语法**——HTML 中的链接不享受 `vsce` 重写，相对路径在 Marketplace 与扩展详情页必然失效（v1.4.4 曾因导航行改为 HTML 表格 + 相对 `href` 导致链接全部失效）；
- 两种安全写法二选一：
  - Markdown 链接 + 相对路径（如 `[English](README.en.md)`）——依赖 `vsce` 重写，GitHub 与详情页均可跳转；
  - HTML 链接 + **绝对 GitHub URL**（如 `<a href="https://github.com/…/blob/master/doc/总览.md">`）——不依赖重写，且 HTML 的对齐/布局能力（如导航行右对齐）仅在这种写法下安全；
- **禁止 HTML 链接 + 相对路径**的组合；
- 每次发布前在扩展详情页实测 README 链接可跳转。

## 5. 版本号判据

产品版本号（`package.json` 的 `version`）是否更新，唯一判据是**本次修改是否影响发布包行为**：

- **影响发布包行为 → 必须更新版本号**：
  - 用户可见的运行期行为变化（新功能、行为修正、UI 变化）；
  - 清单声明变化（`contributes` 的命令 / 视图 / 菜单 / 配置项）；
  - 随包运行内容变化（`dist/` 产物中可达代码的行为、运行时依赖、本地化文案）；
- **不影响发布包行为 → 一律不更新版本号**：
  - 单元测试（`test/`、`out-test/` 被 `.vscodeignore` 排除，见 §4.6）；
  - 工程脚本与编译/打包设施（`scripts/`、`.vscode/` 均不随包）；
  - 文档（`doc/`，含本文档与 CHANGELOG 自身）；
  - 仅作用于测试构建的源码改动——虚拟 HAL 全部特性（开机链路、混排、控制面）在发布包中运行时不可达（§4.1 开关恒 `false`），且产品化打包保证发布清单无测试特性（§4.3）；
- **判据存疑时以「发布 VSIX 的用户可感知差异」为准**：对比修改前后各打出的 VSIX，用户在使用中能察觉到的一切差异（面板、命令、设置、行为）都算影响发布包行为。

版本号格式、CHANGELOG 联动（bump 才写 CHANGELOG）与提交流程见 agent-work-agreement skill「版本号与 CHANGELOG」；测试套件版本（`test/package.json`）独立演进，规则见 [开发测试体系规划.md](Test/开发测试体系规划.md) §5.4。
